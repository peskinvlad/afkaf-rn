# afkaf-rn

- **Бета iOS-first:** фоновая геолокация на Android (foreground service,
  `ACCESS_BACKGROUND_LOCATION`) вне скоупа — не делать без отдельного решения.
- **Лейаут всегда LTR** (`lockLayoutLTR` в `src/i18n`): `forceRTL` не
  возвращать, пока экраны не прошли RTL-адаптацию (бэклог).

## Перед production-билдом

- **Обязательный ручной прогон на dev-клиенте перед каждым
  `eas build --profile production`.** Прод-билд 0.1.0(1) ушёл в TestFlight с
  двумя регрессиями, которых не было бы при этом прогоне (пустая карта +
  мигание, молчаливый Google-вход). Пройти на реальном устройстве:
  - **Карта, зум в обе стороны** — пинч приближает/отдаляет плавно, карта не
    улетает в «сплошную воду», логотип Apple на месте.
  - **Метки на городском зуме** — водопои, парки, пользовательские метки видны
    (в Гуш-Дане их ~1600); при сильном отдалении инфраструктура пропадает и
    возвращается без мигания карты.
  - **Вход Apple** — открывается системный шит, вход проходит.
  - **Вход Google** — открывается браузер с выбором аккаунта, вход проходит.
    (До снятия временных Alert'ов — любая ошибка видна текстом.)
  - **Старт и завершение прогулки** — трекинг пишется, сводка сохраняется.
  - **Свернуть приложение на минуту во время прогулки** — вернуться: трек не
    оборвался, позиция и статистика на месте.
- **После любого изменения переменных в EAS — сверить с локальным `.env`** через
  `eas env:list --include-sensitive`: значения должны совпадать символ в символ
  (вставлять только копированием, не набирать руками). Битый один символ в
  Supabase anon key ронял ВСЕ запросы к БД в релизе — меток на карте не было.
- **Пропы-объекты MapView — только стабильные ссылки.** `initialRegion`,
  `mapPadding` и любые другие объектные/массивные пропы MapView передавать
  константой, `useMemo` или `state`/`ref` — НИКАКИХ инлайн-литералов. На New
  Architecture (Fabric legacy-interop) `react-native-maps` переприменяет проп
  при смене ссылки: инлайн-`initialRegion` давал новый объект на каждый рендер
  и откатывал камеру к нему после каждого пинча (регресс 0.1.0(1)).
- **Правило для ассистента:** перед тем как предложить/подготовить
  `eas build --profile production`, СНАЧАЛА напомнить владельцу про этот прогон
  и дождаться подтверждения, что он пройден. Не запускать прод-сборку без него.

## Карта (MapView)

- **Измеренные экранные значения нельзя лить в нативные пропы MapView
  (`mapPadding` и т.п.) без жёстких границ; горизонтальные отступы — только
  константами.** `measureInWindow` меряет в координатах окна и во время slide-in
  перехода навигации вернул `x = 446` при ширине окна `430` → `mapPadding.left`
  обнулил видимую ширину карты → `longitudeDelta 0`, переворот долготы на 180°
  («океан») и пропавший логотип Apple. `left` сейчас всегда константа экрана
  (`lib/mapInsets.ts`), из замера берётся только `y` для `bottom` (с кламп-фолбэком).
- **На каждом `MapView` обязателен `cameraZoomRange` (стабильная константа,
  `lib/mapConfig.ts`).** Без него в `react-native-maps@1.20.1` активен legacy
  zoom-clamp (`applyLegacyZoomConstrains`), который при вырожденном регионе
  (`longitudeDelta 0`) после каждого жеста переставляет карту и заворачивает
  долготу. `minZoomLevel`/`maxZoomLevel` на Apple Maps **не использовать** (они
  deprecated и это и есть легаси-путь) — ограничение зума задавать через
  `cameraZoomRange.{min,max}CenterCoordinateDistance`.
- **«Работает на dev-клиенте» ≠ «работает в релизе».** Карта и входы (Apple,
  Google) проверяются на **preview-билде с чистой установки** до любого
  production-билда — «океан», RTL-раскладка и линковка нативных модулей
  воспроизводятся только в Release. Для диагностики карты в релизе есть
  рантайм-оверлей: DevPanel (5 тапов по строке версии на About, только
  `DEV_USER_IDS`) → «Отладка карты» → тумблер **Map debug overlay** (действует
  сразу, без перезапуска).

## Работа с БД (Supabase)

- **Снапшот схемы — каталог `supabase/`, это источник правды.** Снимки по
  категориям: RLS-политики `supabase/policies/*.sql`, функции
  `supabase/functions/*.sql`, триггеры `supabase/triggers.sql`. DDL таблиц и
  колонок пока **не снят** — единый снимок таблиц ведётся в
  `supabase/tables.sql` (сейчас заготовка/TODO, заполняется по мере правок).
  Перед задачей, читающей или пишущей в БД, — сначала свериться со снимком.
- **Чтение БД через Supabase MCP разрешено** (проверка схемы, отладка,
  сверка данных). **Любая ЗАПИСЬ в БД** (DDL, миграции, INSERT/UPDATE/DELETE
  вне приложения) — только через **ручной стоп**: выдать SQL текстом,
  дождаться ответа «выполнил», после этого обновить снапшот схемы в
  `supabase/` (нужную категорию и/или `supabase/tables.sql`) **тем же
  коммитом**.
- **`markers`: строки не удаляются, только фильтруются по `expires_at`** —
  история нужна для сводки района.
- **Типы меток (`markers_type_check`):** `park`, `water`, `danger`, `hazard`,
  `aggressive_dog`, `forbidden`, `dog_park`, `food`. Канон в клиенте —
  `src/lib/markerConfig.ts` (`MARKER_CONFIG`). Тип не в `MARKER_CONFIG` рендерится
  нейтральным серым 📍 (fallback в Map/Walk/Callout/filter), краха нет.
  - **`water`/`park`/`dog_park` — инфраструктура (кураторские).** Ставит только
    куратор через service_role / SQL (постоянные, `expires_at = NULL`, `user_id`
    куратора `e57637d6-7b83-465c-8263-6ca0fa822ab4`). Триггер
    `markers_guard_insert` блокирует их вставку обычным юзером (`auth.uid()` не
    NULL) через `RAISE EXCEPTION 'PT403'`. В селекторе клиента их нет.
  - **`food`** — будущий пользовательский тип (пост-бета), в клиенте пока не
    заведён; в триггере ограничений на него нет (общий путь: rate-limit + 24h).
  - **`water_sources`** дедуплицируется по `osm_id` (UNIQUE INDEX
    `water_sources_osm_id_key`) — импорт идёт `ON CONFLICT (osm_id) DO NOTHING`.

## Security backlog (post-beta)

Найдено аудитом перед первой TestFlight-сборкой (2026-09-13). Не блокеры
беты; разбирать после. Критичных дыр (обход auth, утечка `service_role`) нет.

- **Сессия Supabase в SecureStore (Keychain).** Сейчас токены в AsyncStorage
  (`src/lib/supabase.ts`, `storage: AsyncStorage`) — открытый текст в песочнице.
  Перейти на `expo-secure-store`; лимит Keychain ~2 КБ, JWT крупнее — нужен
  адаптер (чанкинг или AES-ключ в SecureStore + шифртекст в AsyncStorage).
- **Квантование координат для `visibility='everyone'`.** RLS `active_walks`
  (`supabase/policies/active_walks.sql`) без серверного гео-фильтра; 2 км
  режется на клиенте (`src/hooks/useNearbyDogs.ts`). Владельцы `everyone`-прогулок
  отдают точные live-координаты всем. Дефолт — `friends`, так что риск opt-in.
  Квантовать/rate-limit'ить `everyone`-ветку.
- **`marker_votes` SELECT `USING(true)`** (`supabase/policies/marker_votes.sql`)
  раскрывает `user_id` голосовавших. Сузить видимость.
- **`get_trust_status` с произвольным `p_user_id`**
  (`supabase/functions/get_trust_status.sql`, не SECURITY DEFINER) — можно
  посчитать чужой confirmed-count. Низкая чувствительность.
- **Убрать `EXPO_PUBLIC_MAPBOX_TOKEN` из `.env`** — в коде не используется
  (в бандл не инлайнится), но токен лежит в локальном `.env`.
