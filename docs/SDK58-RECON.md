# Переезд на Expo SDK 58 — разведка (25.11.2026)

Только чтение и поиск: ни одна строка кода не менялась. Цель — понять, что сломается,
в каком порядке идти и сколько сборок это стоит. Делать переезд — **после релиза
1.1.0 (Mapbox)**, веткой от него; релиз с новым SDK — 1.2.0.

Что проверено, а что нет, помечено явно: **[проверено]** — прочитано в источнике или
в нашем коде сегодня; **[не проверено]** — узнаем только на сборке.

## Где мы и куда

| | Сейчас | Цель |
|---|---|---|
| Expo SDK | 54 (`expo ~54.0.0`) | 58 (на npm `latest` = 58.0.26) |
| React Native | 0.81.5 | 0.88 |
| React | 19.1.0 | 19.2+ (точную версию поставит `expo install --fix`) |
| Xcode на EAS | закреплён `xcode-26.0` | образ `sdk-58` = Xcode 27.1 |
| Мин. iOS | 15.1 | 16.4 (поднято в SDK 56) |

SDK 58 вышел 15.10.2026. Прыжок — через четыре версии (55, 56, 57, 58).
Окно поддержки SDK 54 закрылось с выходом 58: критических исправлений для него
больше не будет. **[проверено]** (changelog SDK 57 и 58)

## Зачем это нам

1. **Сцены (UIScene).** Сборка на iOS 27 SDK без них не запускается на iOS 27 — это
   наш запрет из CLAUDE.md («локально только для iOS 26», «EAS закреплён на Xcode
   26»). В SDK 58 сцены включены по умолчанию: prebuild сам создаёт
   `SceneDelegate.swift`. **[проверено]** После переезда локальная сборка из Xcode 27
   годится для iOS 27, а закрепление образа EAS снимается.
2. **Срок Apple** (~апрель 2027, сборка на iOS 27 SDK) — без SDK 58 его не пройти.
3. SDK 54 больше не чинят.

## Что меняется по шагам (только то, что касается нас)

### 54 → 55 (React Native 0.83)
- Старая архитектура убрана совсем; поле `newArchEnabled` удалено. У нас оно не
  задано, мы уже на новой — **не затрагивает**. **[проверено]**
- Поля `notification`, `edgeToEdgeEnabled`, `androidStatusBar` в app.json удалены/
  устарели. У нас их нет — **не затрагивает**. **[проверено]**
- **`eas update` требует флаг `--environment`.** Это меняет команды публикации из
  CLAUDE.md (`eas update --channel production …` → добавить `--environment
  production`). Обновить CLAUDE.md в том же коммите. **[проверено по changelog,
  точный вид команды — проверить на первой публикации]**
- Нужен новый dev-клиент (так на каждом шаге).

### 55 → 56 (React Native 0.85)
- **Минимальный Xcode 26.4**, минимальная iOS 16.4. Наш закреплённый образ
  `macos-sequoia-15.6-xcode-26.0` для этого шага уже **слишком старый** — менять во
  всех профилях `eas.json`. Пользователи на iOS 15–16.3 обновлений больше не
  получат (iPhone 7, 6s, SE 1-го поколения). **[проверено]**
- Hermes V1 — движок по умолчанию. В 56 у него была утечка памяти при подключённых
  reanimated/worklets (они у нас в зависимостях); исправлено в 57. Значит, **на 56 не
  задерживаемся и не выпускаем**. **[проверено]**
- OTA-обновления становятся «разностными» (bsdiff) по умолчанию — меньше трафика,
  поведение то же. **[проверено]**

### 56 → 57 (React Native 0.86)
- Маленький шаг, для наших библиотек ломающих изменений в changelog нет.
  **[проверено]**

### 57 → 58 (React Native 0.88) — главный шаг
- **Сцены** — см. выше. Нативные папки мы руками не ведём (их создаёт prebuild),
  `AppDelegate` не переопределяем — отдельной миграции не нужно. **[проверено]**
- **Строгие типы React Native по умолчанию.** Глубоких импортов
  `react-native/Libraries/*` у нас нет **[проверено grep]**; типы ref-ов могут дать
  ошибки `tsc` — узнаем при прогоне. Есть временная отсрочка через `tsconfig`.
- **Удалены:** `InteractionManager`, `Touchable`, проп `animated` у `Modal`, пропы
  `backgroundColor`/`translucent` у `StatusBar`; `ImageBackground` устарел. В нашем
  коде ничего из этого не используется. **[проверено grep]**
- **Уведомления:** на переднем плане теперь показываются по умолчанию, если
  обработчик не сказал иначе. У нас обработчик задан (`src/lib/notifications.ts`),
  но поведение подсказок на прогулке («Уже дома?», сближение с меткой) —
  **перепроверить на телефоне**.
- **Ориентация.** На iOS 27 приложения для iPhone становятся «резиновыми»: запрет
  поворота может не действовать. У нас `orientation: portrait` и лейаут только
  вертикальный — **[не проверено]**, смотреть на устройстве с iOS 27 (и на
  складном iPhone Duo, когда появится): не ломается ли экран при повороте.
- **Образ EAS:** псевдоним `sdk-58` указывает на Xcode 27.1; закрепление конкретного
  образа в `eas.json` заменить на него. **[проверено]**
- **Android:** в релизных сборках по умолчанию включён R8 (сжатие кода) —
  библиотеки с рефлексией могут потребовать правил. Касается ветки `exp/android`,
  не этого переезда.
- Node на компьютере: нужен 22.13+ или 24.3+. **Влад: проверить `node -v`.**

## Развилка: что делать со старой картой

- **А. Удалить `react-native-maps` в этом же переезде (как в плане).** Меньше нативного
  кода, нет заплатки, которая может не собраться на RN 0.88. Но откат «вернуть всем
  карту Apple по воздуху» исчезает.
- **Б. Оставить и обновить до версии из SDK 58.** Рубильник живёт, но заплатку надо
  переписывать под новую версию библиотеки, а старая карта на новом SDK — ещё один
  набор экранов для проверки.

Предложение: **А**, при условии что 1.1.0 прожил у пользователей хотя бы пару недель
без откатов на Apple. Решает Влад.

## Порядок работ

1. Релиз 1.1.0 (Mapbox) вышел и стабилен.
2. Ветка `feat/sdk-58` от него. Удалить `react-native-maps` (если вариант А).
3. Шаги 55 → 56 → 57 → 58 **по одному**, отдельным коммитом каждый: `npx expo install
   expo@^5X --fix`, `npx expo-doctor`, `npx tsc --noEmit`, `npx expo prebuild
   --no-install` (проверка, что конфиг и плагины собираются). Это делается в облаке,
   без телефона. Сборку на телефон на промежуточных шагах не делаем.
4. `eas.json`: образ → `sdk-58`; `version` → 1.2.0; команды в CLAUDE.md
   (`--environment`); раздел «iOS-тулчейн» в CLAUDE.md переписать.
5. **Сборка 1: dev-клиент** (EAS). Первым делом — открывается ли Mapbox. Если нет —
   стоп, разбираемся с библиотекой, остальное бессмысленно.
6. Полный чек-лист + настоящая прогулка (фон, шагомер, автозавершение, подсказки).
7. **Сборка 2: preview** с чистой установки, чек-лист.
8. **Сборка 3: production** → TestFlight → App Store.

**Сборок EAS минимум три**, реально 4–6 (первая после такого прыжка редко собирается
с первого раза). Работы — 2–3 сессии плюс прогулка.

## Риски, от большего к меньшему

1. **Mapbox на RN 0.88 / iOS 27 / сценах** — не подтверждено ничем, кроме того, что
   библиотеку активно ведут. Проверяется первой сборкой.
2. **Фоновая запись прогулки** после смены жизненного цикла приложения на сцены:
   возврат из фона, перезапуск системой. Только полевая проверка.
3. **Ориентация и «резиновое» окно на iOS 27** при вертикальном лейауте.
4. Вход Google (редирект `afkaf://auth/callback` теперь доставляется через сцену) и
   вход Apple — оба в чек-листе.
5. Отсечение iOS < 16.4.

## Чего в разведке нет

- Полных changelog-ов пакетов на GitHub (читались только сводные страницы выпусков).
- Проверки, что Expo разрешает прыгать через версии: в прочитанных страницах об этом
  ничего; идём по одной версии как более безопасным путём.
- Android (`exp/android`) — отдельный разговор.
