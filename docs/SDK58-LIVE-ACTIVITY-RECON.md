# Expo SDK 58 + Live Activity — разведка

Дата: 25.11.2026. Только чтение кода (main `abf214b`, ветка `exp/mapbox-sdk58`) и
официальной документации Expo / Apple. Ничего не собиралось и не запускалось на устройстве.

## Коротко

1. **Live Activity на SDK 54 сделать нельзя нормально.** Официальный путь — библиотека
   `expo-widgets` (виджеты и Live Activity пишутся как React-компоненты, без Swift).
   Она стабильна с SDK 56. Прежняя сторонняя `expo-live-activity` (Software Mansion)
   заархивирована 1 июня 2026 и помечена deprecated — на неё не садимся.
2. **Апгрейд до SDK 58 закрывает сразу три темы:** UIScene (в SDK 58 включён по умолчанию,
   дедлайн Apple ~апрель 2027), Live Activity, виджет температуры на домашнем экране
   (тот же `expo-widgets`). Плюс локальные сборки Xcode 27 начнут запускаться на iOS 27
   (сейчас телефон Ани тестируется только через EAS).
3. **Порядок: сначала Mapbox (на SDK 54), потом SDK 58** — как решили 21.11.2026.
   Главный риск апгрейда — наш патч карты (см. таблицу рисков): на новом SDK
   react-native-maps придётся обновить, и патч отпадает. Если к апгрейду карта уже на
   Mapbox, react-native-maps удалён вместе с патчем и чинить нечего. Обратный порядок
   означает чинить старую карту на новом SDK, чтобы потом её выбросить.
   Цена: Live Activity выходит позже (после Mapbox). Срок Apple (~апрель 2027) при этом
   выдерживается: Mapbox — декабрь–январь (1.1), SDK 58 + Live Activity — февраль–март (1.2).
   Условие: сборка `exp/mapbox-sdk58` на Mac Влада подтверждает, что Mapbox живёт на 58.
   Если нет — порядок пересматриваем.
   (В первой версии этого документа стояло «SDK первым» — это была ошибка: вывод написан
   без сверки с решением от 21.11, новых фактов против него нет.)

## Что известно про SDK 58 (источник — changelog Expo)

- Вышел 15.10.2026. React Native 0.88, React 19.3, «built for iOS 27».
- Поддержка сцен (UIScene) встроена; флаг `ios.enableSceneSupport` из SDK 57 убирается.
- Node не ниже 22.13 (на 22-й линии). Android `compileSdkVersion` 37.
- С 54 до 58 — четыре шага за один раз (55, 56, 57, 58): изменений накопилось много,
  но `exp/mapbox-sdk58` показал, что наш код собирается после пяти точечных правок.

## Что уже проверено веткой `exp/mapbox-sdk58` (коммит 23cd6cd)

- `expo` 58.0.26, RN 0.88.1, `react-native-maps` 1.29.11, `@rnmapbox/maps` 10.3.18,
  reanimated 4.7.1 + worklets 0.13.0, `expo-notifications` 58.1.9.
- Понадобились правки: `StyleSheet.absoluteFillObject` → `absoluteFill` (10 файлов),
  явная зависимость `expo-file-system`, фолбэк для `AppState.currentState = null`,
  тип ref у ScrollView, тип children у `MarkerAnimated`.
- `tsc` чистый, `expo config` и `prebuild` (iOS + Android) проходят. **Не собиралось.**
- Патч `patches/react-native-maps+1.20.1.patch` (фикс прыжков маркера через setFrame)
  **отключён** — для 1.29.11 его нет. Это главный риск апгрейда (см. ниже).

| Риск | Почему | Как снять |
|---|---|---|
| Карта: прыжки/пропадание маркеров | Патч написан под react-native-maps 1.20.1; на 1.29.11 поведение маркеров на Fabric другое (в 1.29.5 чинили размер снапшота) | Чек-лист «Перед production-билдом» из CLAUDE.md на dev-сборке: зум, ~1600 меток, фильтр вкл/выкл, свой маркер |

| Уведомления с кнопками и звуками | `expo-notifications` 0.32 → 58.x, плагин звуков | Все 5 видов из DevPanel «Показать сейчас» + кнопка с экрана блокировки |
| Вход Apple / Google | Сцены меняют путь диплинков и OAuth-редиректов | Вход обоими способами на чистой установке |
| OTA | `runtimeVersion` = версия приложения: новая сборка = новая версия (1.1.0); OTA для 1.0.0 и 1.1.0 идут раздельно | После выхода 1.1.0 чинить 1.0.0 по воздуху можно, но отдельной публикацией из старого коммита |
| EAS-образ | Во всех iOS-профилях закреплён Xcode 26 | Сменить на образ с Xcode 27 в том же коммите, что и апгрейд; правило в CLAUDE.md переписать |
| Android | compileSdk 37, канал/каналы уведомлений, foreground service | Отдельно в `exp/android`, не блокирует iOS |

## Live Activity: как это ложится на прогулку

**Что показываем:** экран блокировки и Dynamic Island во время прогулки — время, километры,
температура асфальта; кнопка «Завершить».

**Ограничения Apple, важные для нас:**
- Запустить Live Activity можно только когда приложение на экране. Нам подходит: прогулка
  стартует свайпом в приложении.
- Обновлять из фона — через ActivityKit, пока приложение живёт в фоне. У нас оно живёт
  (фоновая геолокация во время прогулки), и JS уже выполняется в обработчике GPS — туда же
  ставится обновление километров. На форумах Apple есть жалобы на нестабильные фоновые
  обновления без пушей, поэтому **это первое, что проверяем на устройстве** (риск-чек, как
  с кнопкой «Я здесь»).
- Таймер прогулки тикает сам: системный текст-таймер не требует обновлений.
- Живёт максимум 8 часов, потом система её гасит. Для прогулок достаточно; заодно это
  естественный предохранитель от «забытой прогулки».
- Обновления пушами (с сервера) нам не нужны — `enablePushNotifications` не включаем.

**Что добавляется в проект:**
- `expo-widgets` + `@expo/ui`, config-плагин: отдельная цель «расширение виджетов»
  (свой bundle id, например `com.afkaf.app.widgets`) и App Group
  (`group.com.afkaf.app`). EAS сам выпустит второй профиль подписи; в dev-варианте —
  свои id (`com.afkaf.app.dev.widgets`).
- Это нативное изменение → только новая сборка, версия 1.1.0.

**Этапы (каждый — отдельная проверка на телефоне):**
1. (После Mapbox.) Апгрейд main до SDK 58 без новых фич → dev-сборка → чек-лист.
2. Риск-чек Live Activity: «пустышка» с таймером и счётчиком, который JS увеличивает из
   фонового обработчика GPS. 15 минут с выключенным экраном: счётчик растёт или нет.
3. Боевая Live Activity прогулки (текст HE/RU/EN, кнопка «Завершить» через уже
   существующий обработчик автозавершения).
4. Виджет температуры асфальта на домашний экран (тот же плагин, та же сборка).
5. Интро-анимация Lottie и переход на WeatherKit — в ту же сборку 1.1.0, как и планировалось.

## Что нужно от Влада

1. Собрать `exp/mapbox-sdk58`: профиль `development-mapbox`, из отдельной папки
   `afkaf-rn-sdk58`. Проверить две вещи: тестовый экран Mapbox и обычную карту
   (зум, метки, фильтр, свой маркер). От результата зависит, безопасен ли порядок «Mapbox → SDK».
2. Если пункты зелёные — стартуем Mapbox на SDK 54 (новая ветка от main + 9 коммитов
   тестового экрана). Апгрейд SDK — отдельной веткой после выхода Mapbox.
