# afkaf — продуктовые правила

Этот файл — для любого агента или человека, который пишет код afkaf.
Технические правила (сборки, карта, БД, OTA) — в `CLAUDE.md`. Здесь — **что**
мы строим и **чего не строим**, и почему. Если задача противоречит этому
файлу — остановись и спроси владельца (Влад), не «улучшай» молча.

## Что такое afkaf

Приложение для безопасных прогулок с собакой в Израиле (сейчас — Гуш-Дан:
Ришон — Бат-Ям — Холон — Яффо — Тель-Авив — Рамат-Ган — Гиватаим — Бней-Брак —
Рамат-ха-Шарон — Герцлия). iOS и Android, иврит (основной), английский,
русский.

Родилось из реальной проблемы владельца: горячий асфальт израильским летом,
гусеницы-шелкопряды, грязные пляжи после дождя.

Позиция на рынке: **жара асфальта + карта опасностей от соседей + запись
прогулки, под Израиль.** Местные конкуренты — соцсети для собачников без
расчёта жары; мировые «hot pavement» приложения — только погода, без
местного сообщества.

Главный урок рынка: социальные приложения для собак умирают без
пользователей. **afkaf обязан быть полезным в одиночку** — жара, вода,
площадки, свои метки работают, даже если в районе никого нет.

## Принципы

- **Ценность до регистрации.** Гость видит карту, жару, метки. Логин —
  когда нужен (поставить метку, друзья, отметка на площадке).
- **Советчик, а не охранник.** Предупреждаем (жара, опасность), но решение
  за человеком: «Всё равно иду» есть всегда, просто менее заметно.
- **Приватность по умолчанию.** Сомневаешься — показывай меньше.
- **Доверие сообщества не монетизируется.** Монетизация — после того, как
  продукт нужен людям; и не за счёт данных и безопасности.
- **Ориентир по UX — Apple.** Максимальный комфорт, тёплые короткие тексты.
- **Тон без негатива.** Итог прогулки никогда не ругает («плохая прогулка»
  — нет). Тексты тёплые, с кличкой собаки.

## Чего мы НЕ делаем (твёрдо)

- Чат внутри приложения (для связи — мост в WhatsApp).
- Лайки, комментарии, ленты.
- Профили-подписчики, фолловеры.
- Рейтинги собак и владельцев.
- Список «Не дружим» / любые негативные отношения между людьми.
- Пользовательские метки инфраструктуры: `water`, `park`, `dog_park`,
  `forbidden` («нельзя с собаками») ставит только куратор (импорт/SQL).
  Пользователи ставят только временные метки.

## Приватность — как устроено

- **Видимость на прогулке:** `everyone` / `friends` / `nobody`. Выбор
  делается при первой прогулке (bottom sheet), «Все» рекомендуем, но не
  выбираем за человека.
- **Домашняя зона** скрывает **твою** позицию рядом с домом; ты при этом
  видишь друзей. Зона хранится только на телефоне.
- **Площадки:** ручное «Я здесь» = согласие быть показанным по имени.
  Автоприсутствие = только анонимный счётчик, и только когда людей ≥2.
  Внутри своей домашней зоны отметки нет.
- **Метки анонимны** — автор в интерфейсе не раскрывается.
- **Блокировка** прячет людей в обе стороны, но **не метки** (подробно —
  `CLAUDE.md`, раздел «Модерация»).
- Никаких подсказок и функций, которые раскрывают чужой распорядок
  (где и когда человек гуляет) тому, кто на это не соглашался.

### Скриншоты и домашняя зона (решение 25.11.2026)

- Домашняя зона на главной карте постоянно не показывается: кнопка-«глаз» включает её
  на несколько секунд (появится вместе с переездом на Mapbox).
- Скриншот, сделанный пока зона видна, — предупреждение «На снимке видна твоя
  домашняя зона».
- Экран настройки зоны закрыт от скриншотов и записи экрана (с версии 1.1.0).
- Главную карту от скриншотов НЕ закрываем: ими делятся, чтобы предупредить о метках.
- Друг видит на странице друга только месяц и год рождения собаки, не точную дату.

## Метки

- Типы: `danger`, `hazard` (общая «угроза», не обязательно яд),
  `aggressive_dog`, `food` (в базе есть, в клиенте — после беты),
  инфраструктура `water` / `park` / `dog_park` / `forbidden` (кураторская).
- Временные метки живут по TTL и подтверждаются соседями
  («Ещё здесь» / «Исчезло»). В иврите голос по метке — «סימון», не «הצבעה».
- План (ещё не сделано): сезонность — свойство типа метки (с какого по
  какой месяц показывать), вне сезона метки скрываются, данные не удаляются.

## Тексты и языки

- Три языка всегда синхронно: одинаковое число ключей в he / en / ru.
- Русский — на «ты».
- Иврит — нейтральное множественное число (обращение к паре человек+собака
  и без рода).
- Владелец сам проверяет все три языка; внешний носитель не нужен.
- Сообщения во внешние службы (например, отчёт в мэрию) — всегда на иврите,
  подпись отдельной строкой: «נשלח בעזרת afkaf». Без рекламы и ссылок.

## Уведомления

- Только полезные и редкие. Тихие часы 23:00–07:00 (кроме «Уже дома?» и
  «Ты всё ещё гуляешь?»). Time-sensitive — только у этих двух.
- Кнопки прямо в уведомлении, чтобы не открывать приложение.
- Звуки — собственные (`assets/sounds/`), без лая.

## Профиль собаки

- «Характер» (дружелюбный / нейтральный / реактивный) — один выбор, про безопасность
  при встрече. Метки характера — отдельно, до 5 из списка (`src/lib/dogTraits.ts`);
  ключи не переименовываем, только добавляем (в БД — ограничение `dogs_traits_check`).
- День рождения: поздравление только для точных дат, в 10:00, с возрастом в тексте.

## Дорожная карта (решения 21–25.11.2026)

- **1.1.0 — Mapbox** на Expo SDK 54. Обе карты в сборке, выбор — `useMapEngine()`;
  откат на старую карту — обновлением по воздуху. План: `docs/MAPBOX-MIGRATION.md`.
- **1.2.0 — Expo SDK 58** + Live Activity прогулки + виджет температуры; здесь же
  удаляется react-native-maps. Срок Apple — около апреля 2027.
- Порядок «Mapbox → SDK» не меняем без новых фактов: Mapbox убирает главный риск
  апгрейда (патч карты).
- Серверные пуши («друг вышел гулять») — после решений владельца по
  `docs/SERVER-PUSH-PLAN.md` (в ветке `docs/sdk58-live-activity-push`).
- Монетизация: до ~1000 активных в месяц ничего не продаём. Безопасность (метки,
  температура, предупреждения, жалобы), друзья и площадки бесплатны всегда;
  геоданные людей не продаются, партнёрам и городам — только обобщённые цифры.

## Как с кодом работают агенты

- Каждая задача — своя ветка `feat/...` / `fix/...` / `docs/...`.
  **В `main` агенты не мёржат, OTA не публикуют, сборки не запускают.**
- **Запись в БД — никогда.** Только SQL-черновик в отчёте; применяется
  после «ок» владельца (правило в `CLAUDE.md`).
- Только JS/TS без нативных изменений, если задача прямо не говорит иное.
- Проверка перед сдачей: `npx tsc --noEmit -p .` чистый, ключи i18n сходятся.
- Проверка на устройстве — всегда за владельцем; в отчёте — короткий
  чек-лист, что именно потрогать на телефоне.
