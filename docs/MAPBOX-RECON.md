- `initialRegion` — везде; на Map/Walk константой (правило CLAUDE.md), на WalkSummary и PrivacyRadius — инлайн-объектом (формально нарушает правило, но экраны статичные).

- `mapPadding` — Map и Walk: двигает логотип Apple/Legal к чипу температуры и сдвигает визуальный центр.

- `onRegionChange` / `onRegionChangeComplete` — Map, Walk, AddMarker: отличить жест от программного движения, обновить якорь пузыря, гистерезис инфраструктуры, возврат в круг.

- `zIndex` — 1 метки, 2 друзья, 3 я. `tracksViewChanges` — включён 0,5 с, потом выключается (кроме моего маркера).
- image-пины — только на `exp/android`.

#### Вариант C (clamp `atIndex`) — отклонён 05.10.2026

Коммит `e923cb4` клэмпил индекс вставки в `AIRMap.m` (если больше длины — в
конец), чтобы убрать краш «index beyond bounds». На локальной Release-сборке
«afkaf dev» это дало **регрессию**: краша нет, но **своя стрелка пользователя
пропадала при повторном включении типов меток в фильтре**. Причина: клэмп не
лечит рассинхрон индексов `react-native-maps` на New Architecture, а **маскирует**
его — вставка молча уходит в конец, нативный порядок детей расходится с React, и
слот стрелки становится жертвой. build 3 (без клэмпа) ту же проверку проходит.
Откат — коммит `6901277` (revert), патч `setFrame` сохранён; защиту от краша
обеспечивает JS-фикс A+B (стабильные ключи, всегда смонтированные стрелка/линия).

**Правильное решение (не для билда 4):** убрать из фильтра вставку/удаление детей
карты — метки всегда смонтированы, скрываются через `opacity` без размонтирования
(как уже сделано для стрелки), **в паре с кластеризацией/bbox** (иначе ~1600
всегда смонтированных пинов бьют по перфу). Альтернатива в корне — переход на
**Mapbox** (`@rnmapbox/maps`), где этого класса багов нет (см. разделы 3–5 выше).

### Запись маршрута — зависит ли от карты

**Нет, независима.** `src/lib/walkTracking.ts` импортирует только `expo-location` и `expo-task-manager`; маршрут хранится в `routeRef` внутри WalkScreen, карта его только рисует. `gpsQuality`, `autoFinish`, `walkFinalize`, `parkCheckin`, `zoneDwell` карту не знают. Единственные связки: `useSmoothedPosition` (тип `AnimatedRegion` из react-native-maps) и формат координат `{latitude, longitude}` — в Mapbox порядок другой: `[долгота, широта]`. Это классический источник ошибок при переезде.

## 3. Библиотека @rnmapbox/maps

Проверено по npm и GitHub 30.09.2026.

- **Версия:** `10.3.5` от 22.07.2026 (последняя стабильная). Репозиторий живой: коммиты 19–21.09.2026, 160 открытых issues.
- **Совместимость:** требует `react-native >= 0.79`, `expo >= 47`, **только New Architecture** (с 10.3.0 старая архитектура удалена). У нас RN 0.81.5, Expo 54, New Architecture включена — подходит. Сама библиотека разрабатывается на `expo ^54.0.10` и RN 0.81.1 — то есть **наш сетап для неё родной**, в более новый Expo она не упирается. Попутно: ветка `exp/old-arch` с Mapbox несовместима.
- **Нативный Mapbox SDK:** по умолчанию 11.23.1 (iOS и Android).
- **Config plugin** (кусок настройки, который Expo применяет при сборке): строка `"@rnmapbox/maps"` в `plugins` в `app.json`, опционально `RNMapboxMapsVersion`. В Expo Go не работает — только своя сборка (у нас так и есть).
- **Секретный download token (`sk.`) больше не нужен.** В podspec библиотеки: «download token is no longer required»; в `android/install.md`: «mapbox lifted auth requirement from downloads». Нужен только публичный `pk.`, он задаётся в коде (`Mapbox.setAccessToken`).
- **EAS Build:** стандартный путь, специальных шагов нет.
- **Локальная сборка Xcode 27** (у тебя стоит Xcode 27.0): в issues нет ни одного упоминания Xcode 27 или iOS 27 — **не подтверждено ни «работает», ни «сломано»**. Проверяется только пробной сборкой.

## 5. Стратегия внедрения

**Обе библиотеки в одном билде + флаг в DevPanel + экраны по одному — рабочий вариант.** Нативно они не конфликтуют. Порядок: WalkSummary → PrivacyRadius → AddMarker → MapScreen → WalkScreen.

Условия, чтобы это было безопасно:
- Код Mapbox подключать «лениво», с проверкой наличия нативного модуля — приём уже есть в проекте (`requireOptionalNativeModule` в `walkTracking.ts`). Иначе JS упадёт на сборке без Mapbox.
- Флаг в DevPanel хранится на устройстве; значение по умолчанию зашито в JS. **Откат через OTA** (обновление по воздуху) = публикация с флагом по умолчанию «старая карта». Работает.
- По правилу CLAUDE.md правки карты — «рискованные»: OTA только после проверки на preview- или dev-сборке.

**Октябрьский dev client (свой bundle id):** да, Mapbox туда класть **нужно и выгодно** — тестеры не затронуты, сборка всё равно делается. Нюанс: плагин в `app.json` попадёт во все профили сборки, т.е. следующий production-билд тоже получит Mapbox (и размер). Если в проде пока не надо — включать плагин условно через `app.config.js` (как сделано для ключа Google Maps на `exp/android`).

**runtimeVersion** (метка «какой JS подходит к какой сборке»):
- Mapbox — нативное изменение. iOS: поднять `version` `0.1.0` → `0.2.0`. Android: `android-1` → `android-2`.
- Текущие тестеры на 0.1.0 **не отрезаются сами по себе**: они перестают получать OTA только когда мы начинаем публиковать из кода с версией 0.2.0. Чтобы не бросить их: выложить сборку 0.2.0 в TestFlight **до** первой OTA под 0.2.0; срочные правки для 0.1.0 публиковать из отдельной ветки, где версия ещё 0.1.0.
- Dev client на OTA не завязан (грузит JS с компьютера) — для него вопроса нет.

**Размер приложения:** Mapbox SDK — крупная нативная библиотека; ориентир — плюс 15–25 МБ установленного размера на платформу на время жизни обеих библиотек (**оценка, не измерял** — узнаем по первой сборке). После удаления react-native-maps на iOS почти ничего не вернётся (Apple Maps встроены в систему), на Android уйдёт Google Maps SDK.

## 6. Токены и безопасность

- **Где лежит старый токен:** в локальном `.env` (`EXPO_PUBLIC_MAPBOX_TOKEN`, в коде не используется) и в локальном `HANDOFF-SESSION-2.md`, строка 66 (файл в `.gitignore`).
- **В git-истории `afkaf-rn` токена нет** — проверил все ветки, включая удалённые. Это важно: репозиторий `peskinvlad/afkaf-rn` **публичный**. Файлов `HANDOFF*` в истории тоже нет. Где именно он утёк в июне, по репозиторию установить не могу — если файл уходил куда-то ещё, считаем токен скомпрометированным и меняем.
- **Осторожно при замене:** старый веб-прототип `afkaf` использует `NEXT_PUBLIC_MAPBOX_TOKEN`. Если это тот же токен и сайт ещё живёт на Netlify — после удаления карта там погаснет, пока не подставишь новый.
- **Где хранить новый:** EAS env, три окружения (development / preview / production), имя `EXPO_PUBLIC_MAPBOX_TOKEN`, лучше **три разных токена** — видно расход по каждому и можно отозвать один. После заведения — сверка с `.env` символ в символ (правило CLAUDE.md).
- **Ограничения токена на мобильных:** публичный `pk.` в приложении всегда можно достать — это нормально и заложено в модель Mapbox. URL-ограничения для мобильных SDK **не работают** (прямо в документации). Реальные меры: только публичные права (`styles:read`, `fonts:read`, тайлы), отдельный токен на окружение, следить за статистикой, при подозрении — заменить. Секретный `sk.` в приложение не класть никогда.
- **privacy.html — что менять** (три языка):
  - строку «Apple Maps — отрисовка карты» заменить/дополнить на Mapbox;
  - Mapbox получает: запросы фрагментов карты (по ним видно, какой район смотрят, и IP-адрес) и **телеметрию** — обезличенные данные об использовании, включая местоположение;
  - фраза «No third-party analytics or crash-reporting SDKs» станет **неточной**, пока телеметрия включена;
  - **телеметрию можно выключить**: в rnmapbox есть `Mapbox.setTelemetryEnabled(false)`. По условиям Mapbox у пользователя должна быть возможность отказа — она встроена в кнопку «i»; если кнопку прячем, нужен свой переключатель. Рекомендую: выключить по умолчанию и оставить кнопку «i»;
  - обновить «ярлык приватности» в App Store Connect (геоданные передаются третьей стороне).

## 7. Цена

- **Бесплатно до 25 000 MAU в месяц** (MAU — уникальное устройство, открывшее карту за расчётный месяц). Дальше **$4 за 1000** (25–125 тыс.), потом дешевле. Для беты — ноль.
- **Dev и тестовые установки считаются** — исключений нет. Переустановка приложения = новый MAU. Несколько устройств и симуляторов — несколько MAU. При лимите 25 000 несущественно.
- **Карта оплаты:** зарегистрироваться можно без неё, но это «пробный» режим: пониженные лимиты и **один токен — создавать, менять и удалять токены нельзя, пока не добавишь способ оплаты**. Значит, для замены утёкшего токена и трёх токенов по окружениям карту, скорее всего, придётся привязать. Списаний при этом не будет, пока мы в бесплатном лимите. Проверь в своём аккаунте, какой у него режим.

7. Рост размера приложения по факту первой сборки неприемлем.

### Рекомендация: **да, но позже**

Почему «да»: почти все наши карт-костыли — следствие одной причины: react-native-maps 1.20.1 работает на New Architecture через слой совместимости, а 1660 меток рисуются как 1660 отдельных экранных элементов. Mapbox решает обе проблемы по конструкции и разрабатывается ровно на нашем сетапе (Expo 54, RN 0.81, New Architecture). Плюс свой стиль и кластеры, одна карта на две платформы, и Android-наработки (PNG-пины) пригодятся.

Почему «позже»: на iOS карта сейчас работает, тестеры гуляют, dev client на айфоне ещё нет. Переезд — около 10 сессий с риском на двух главных экранах, а на Android у библиотеки есть открытые баги на нашем сетапе без ответа мейнтейнеров.

Предлагаемый порядок: **фаза 0 сейчас** (бесплатно, без кода) → **фаза 1 вместе с октябрьским dev client** (Mapbox едет в ту же сборку) → по тестовому экрану и стоп-факторам 1–3 решаем, идти ли дальше.

# Альтернатива: обновление react-native-maps

Дата: 2026-09-30. Только чтение. Источники: `npm view react-native-maps`, GitHub `react-native-maps/react-native-maps` (CHANGELOG, исходники тега `v1.29.11`, issues и PR), `bundledNativeModules.json` из Expo, документация Expo SDK 54.

Пометки в таблицах: **по коду** — прочитал исходники версии 1.29.11; **по issues** — по отчётам других людей; запусков не было, поэтому всё это подтверждается только сборкой.

## A1. Версии и New Architecture

- **Последняя версия:** `1.29.11` от 27.09.2026. Проект очень активен: 11 релизов за сентябрь 2026, 87 открытых issues.
- **Родная поддержка New Architecture (Fabric) появилась в `1.21.0`** (11.04.2025, в changelog: «major release — Fabric Support!»). Наша `1.20.1` — **последняя версия до Fabric**: в ней нет ни одного Fabric-файла, поэтому она и работает через слой совместимости (legacy-interop), откуда наши беды.
- **Требования новых версий:** 1.26.1+ — React Native ≥ 0.81.1 (у нас 0.81.5, подходит).
- Ветка `2.0.0-beta` заброшена с 2024 года, не рассматриваем.
- Что важного в changelog после 1.20.1:
  - 1.22.0 — свой Expo config plugin;
  - 1.24.6 — починка событий региона (#5622);
  - 1.27.0 — новый проп `appleLogoInsets` (двигать логотип Apple, #5851);
  - 1.29.2 — маркер не съезжает, когда его содержимое трансформируется (#6001);
  - 1.29.3 — защита вставки дочерних элементов в Apple Maps (#5871) — это наш краш `atIndex`;

## A2. Совместимость с Expo SDK 54

- **Expo SDK 54 считает правильной версию `1.20.1`** — и в установленном у нас `expo@54.0.35`, и в свежем `54.0.37`. Для сравнения: SDK 55 и 56 — `1.27.2`, ветка main Expo — `1.29.0`.
- **Что будет, если поставить новее:**
  - предупреждение от `expo install --check` и `expo-doctor` («expected version: 1.20.1») — само по себе безвредно, глушится настройкой `expo.install.exclude`;
  - **реальные риски:** Expo эту связку не тестировал. Известный случай #5742 — после перехода на Expo 54 и версию 1.26.x iOS не собирался, пока не добавили плагин библиотеки в `app.json`. Есть открытый #5970 — EAS Build и локальная сборка генерируют разные настройки pod'ов (касается Google Maps на iOS, у нас Apple Maps).
- **Ключ Google Maps на Android по-прежнему нужен** (документация библиотеки и Expo).
  - Ловушка: плагин `react-native-maps` без параметра `androidGoogleMapsApiKey` **удаляет** ключ из манифеста (по коду `plugin/src/android.ts`). На `exp/android` ключ сейчас кладётся через `app.config.js` — при добавлении плагина его надо передавать и туда, иначе карта упадёт.
- **Apple Maps на iOS работает как раньше**, без ключей (`PROVIDER_DEFAULT`).

| Костыль / проблема | Статус в 1.29.11 | Основание |

## A5. Сборка и runtimeVersion

- **Нативная сборка нужна — да.** Меняется нативный код библиотеки. По воздуху это не доставить.
- Значит, как и Mapbox, это едет в октябрьский dev client; для тестеров — новая сборка с поднятой версией (`0.1.0` → `0.2.0`, Android `android-1` → `android-2`). Правила те же, что в п. 5 основного отчёта.

## A6. Побочная находка: `isGesture` на iOS не работает (уже сейчас)

По коду библиотеки поле `isGesture` отдают только Google Maps (Android и Google-провайдер на iOS). **На Apple Maps его нет ни в 1.20.1, ни в 1.29.11** — в документации прямо: «isGesture is supported by Google Maps only».

У нас на нём держатся две вещи на iOS:
- `WalkScreen`: «сдвинул карту рукой → follow отключается». По коду на iOS это не срабатывает — камера должна возвращаться к тебе на следующем фиксе.
- `MapScreen`: «подвигал карту до первого фикса → авто-центр отменяется». По коду тоже не срабатывает.

Не проверял на устройстве. Проверка простая: во время прогулки сдвинуть карту пальцем и подождать 2–3 секунды. Обновление библиотеки этого не чинит; в Mapbox есть нормальный признак жеста.
